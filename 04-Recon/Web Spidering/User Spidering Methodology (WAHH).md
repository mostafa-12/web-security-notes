## User-Directed Spidering Methodology

### 1. Configure the Proxy

Configure your browser to use an intercepting proxy such as Burp Suite.

---

### 2. Browse the Application Manually

Browse the application like a normal user.

Try to:

- Visit every page.
- Click every link.
- Submit every form.
- Complete every multi-step workflow.

#### Test Different Browser States

- JavaScript Enabled / Disabled
- Cookies Enabled / Disabled

Different browser configurations may expose different content and code paths.

---

### 3. Review the Site Map

Review the Site Map generated by the proxy.

For every discovered resource that you did not visit manually:

1. Determine how it was discovered (e.g., "Linked From").
2. Visit it manually.
3. Allow the proxy to parse its response.
4. Repeat the process recursively until no new content is discovered.

> Discovered URL ≠ Crawled URL.

---

### 4. (Optional) Run an Active Spider

After manual exploration is complete:

- Use the discovered content as the spider's starting point.
- Exclude dangerous URLs (e.g., logout, delete, reset).
- Run the spider.
- Review any additional content it discovers.

---

### Final Goal

The Site Map becomes the primary reference for understanding the application's attack surface.

It will later help identify:

- Hidden functionality
- Authentication boundaries
- Entry points
- APIs
- Attack surfaces
